# 专利导航报告改稿

以委托需求、项目类型和交付要求为起点。GB/T 39551.1—2020 提供共同框架。第2至6部分按应用场景选用，第7部分用于核对服务事项。参见[来源与版本](terminology/sources.md)的 R3。

| 项目主要目的 | 对应部分及改稿关注点 |
| --- | --- |
| 区域规划 | 第2部分。区分支撑区域布局与评价区域创新质量。交代区域边界、比较对象和数据口径。 |
| 产业规划 | 第3部分。结合产业链、产业发展和技术态势说明导航结论，必要时以图谱展示已有分析及其关系。 |
| 企业经营 | 第4部分。按投资并购对象遴选或评估、上市准备、技术合作开发、技术引进、产品开发等目标选用对应内容。候选对象、评价结果和经营决策分开写。 |
| 研发活动 | 第5部分。区分评价研发立项与辅助研发过程。保持研发目标、已有分析、候选技术路线及阶段性建议的对应关系。 |
| 人才管理 | 第6部分。区分人才遴选与人才评价。专利署名等数据指标结合贡献材料和评价条件使用。 |
| 服务准备、提供和评价 | 第7部分。内容涉及委托、服务过程、交付或服务评价时，按合同和实际履行情况写，分别说明服务质量和成果运用情况。 |

对照总则第6至9章和第7.2节，检查以下内容。

| 报告内容 | 改稿时核对 |
| --- | --- |
| 需求分析 | 明确报告服务哪项决策，分析对象、地域、时段和任务范围分别是什么。报告题目、导言和结论服务于同一项目需求。 |
| 信息采集范围及策略 | 分清专利文献、统计资料、行业或市场资料和访谈等来源。保留足以解释样本边界、数据覆盖和图表含义的说明。 |
| 数据处理过程与方法 | 分别交代清洗、筛选和标引。保留影响结果的去重单位、申请人归并和技术分类口径。对照正文、图表、数据表及图注，检查分母、日期和单位。 |
| 分析模型和分析过程 | 写清采用哪些数据、指标或关系回答项目问题。“分析模型”可描述指标、分析维度及其关系，按实际方法表述。单一趋势图、申请量或专利数量排名只支持与本指标相称的判断。 |
| 结论和建议 | 每项结论能回到相应数据、比较范围和分析过程。建议写清拟解决的问题、已有依据、对象和可落实的动作。已识别的现象、拟采取的行动和已经实现的效果分别表述。 |
| 成果产出、运用和评价 | 报告、数据集及按需提供的图谱分别说明。区分已经交付、已被采用和应用后产生的效果。涉及绩效时，按材料注明评价主体、指标和结果。 |

## 怎样写数据、结论和建议

- 先写读者需要知道的结果，再解释依据和适用范围。把内部简称换成它所指的对象或结果。所指不清时，按技能入口标出待核事项。删去与理解结果无关的导出记录、复核批次和流转说明，在方法章节或图表旁保留影响结果的规则。
- 写明按什么计数、怎样去重、用什么作分母。申请、公开文献和同族各用原统计单位。技术分支名与检索表、图例或数据标签对应时保留原名，可在相邻说明中解释。遇到申请人、权利人或发明人的表述与图表标题不一致，保留原统计主体并标出待核。共同申请计入各申请人名下时，合计占比要说明这种计数方式。排名以图表实际采用的申请人归并规则为准。集团关系未经核实，把合并试算及相关排名列为待核。
- 趋势先写清按申请日、公开日还是授权日归年，并交代截止日。已知近期申请尚未全部公开时，说明这对比较的影响。“目前检得的申请少于上一年”只描述已检得的数据。申请人来源与公开地域分别说明各自所用字段。涉及销售地域或权利有效地时，核对相应证据。
- 正文、摘要、图表、图注和附表用到同一数字时，核对截止日、纳入条件、计数单位及分母。材料说明了口径差异，就在各处写清。检索结果有重叠时，说清哪些检索条件检得了同一文献。判断技术之间的关系时，写明文献内容支持的结论。数字冲突且原因未明时，保留原值并注明待核位置。
- 让建议接得上发现。材料给出了实际问题、可选方案和验证指标，就按这个顺序写清要解决什么、比较什么、怎样决定。仅有专利文献公开的方案时，按公开内容表述。初筛发现相关专利时，写清筛查结果及拟核查的法域、法律状态和权利要求。报告已有侵权风险判断时，核对目标法域的权利状态及实际产品或工艺与适用权利要求的比对依据。

优先用委托方认可的报告结构。专项部分用来校对分析内容，不为套章节而增加稿件中没有的工作或结论。术语和统计口径见[报告、检索和统计](terminology/reports.md)。

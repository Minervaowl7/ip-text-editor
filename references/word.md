# Word改稿

Word文件既是内容来源，也是版式依据。环境具备可靠的DOCX结构化修订工具时优先复用；如何判定改写边界和删改范围，仍以本技能规则为准。

## 修改前准备

1. **锁定输入与副本**：确认唯一输入文件与另存输出位置，原稿保持只读不动。读取正文、表格、标题、图表说明及批注，提取用户标黄高亮并结合上下文判断；标黄本身不自动等于整段删除。
2. **建立可核对改动清单**：将每处调整记为“唯一定位（段落/表格位置）+ 原文 + 新文或删除”，并区分用户明确要求的删除与普通顺句调整。有段落标识时优先用段落标识，索引用于复核。标题、图表说明与表内文字在授权范围内的也可编辑，保留编号与对应关系。
3. **先看既有修订与批注**：普通改稿保留原有的修订和批注，除非用户要求处理。本轮改动与既有修订相交时，先核对接受修订后的可见版本与原版本；无法安全写入的部位保留原样，在交付说明中记明位置与原因，继续改其余部分。

## 写回规则

- **保护原有文档结构**：优先使用精确的文字片段（run）级修订工具。改动跨越多个文字片段，或涉及域（交叉引用、目录、页码）、书签、超链接与既有修订时，走对应的高级结构编辑路径；**严禁把整段清空后重写，也严禁把Word转成纯文本再拼回全文。**
- **保持格式与真实修订**：插入和删除保留真实Word修订记录，沿用原有字体、字号和段落、表格样式。整段删除时同步标记段落结束符的删除，避免在Word里全部接受修订后留下多余空段。
- **审阅稿与净稿严格分流**：审阅稿里的删除修订仍可被查阅或恢复。用户要求彻底删除的文字，以及工具身份、会话标识与本机路径，不得留在任何交付文件的删除修订或批注中。交付对外净稿前，应先确定最终可见文本，再彻底清除待删内容及旧修订痕迹；若需同时交付审阅稿，保留其余可审阅的修改，并在说明中列出哪些敏感或过往内容已彻底移除。
- **审阅高亮与修订署名**：用户用来标注问题的黄色高亮，在对应位置处理完成后予以清除；无法确定改法的保留标黄并在正文外说明。清除高亮不得扩大为统一重刷全文字体、颜色或版式，保留承载正文信息的格式（如表头底色、图例配色、区分层级的加粗）。修订署名优先使用用户指定名称；未指定时，中文文稿默认使用中性的 **审阅**（英文文稿使用 `Reviewer`），并在交付说明中简述；严禁填入任何生成工具或模型身份。

## 无配套DOCX修订工具时怎么处理

如果当前环境没有可靠的DOCX结构化修订工具（或文档内含复杂公式、OLE嵌入对象、交叉域导致脚本写入有损版式风险）：

- **不要强行用纯文本覆盖重建原文档**，否则会破坏目录域、交叉引用、自动编号、页眉页脚与表格样式。
- **改交“带精确定位的修订对照表”**（按 `P#` 段落号或 `表X-第R行第C列` 列出原文、建议改法与修改原因），由用户在原Word中对照处理，或在交付说明中如实提示工具限制。
- 若自行使用底层XML操作写回，必须先验证接受全部修订与拒绝全部修订后的完整文本一致无损，再做页面渲染与来源信息脚本检查。

## 验证与交付

- **一致性与对应关系核对**：对照改动清单逐处核查最终可见文字，确认未越过授权范围，编号、目录、表格、图题及交叉引用依然一一对应；复核技术与法律含义、权利状态和计量单位，不能只核对数字串或段数是否相同。
- **文档包与渲染检查**：验证OOXML包与关系结构完好；在办公软件或转换预览中核对接受全部修订后的文本，抽查拒绝修订能否准确恢复原文；渲染检查受改动影响的页面，重点排查跨页断行、字体漂移、表格撑裂与多余空白段。

## 来源信息检查

对准备交付的每份 `.docx` 最终文件执行以下检查（局部写回或另存转换都可能带入或重新写入工具属性）：

1. **检查文档属性**：核对 `docProps/core.xml` 的作者、最后修改者等核心属性，`docProps/app.xml` 的应用程序、生成器和模板，以及 `docProps/custom.xml` 中的自定义工作标识。保留来自原稿或用户指定的真实署名与必要属性，清空工具写入的来源值。
2. **清理隐蔽残留与外链**：排查页眉页脚、批注、删除修订、隐藏文字、对象说明、XML注释与外部关系中的本机路径、工具说明和会话标识；保留正常可读的引用、有效域及应保留的批注和修订。检查新增或可疑图片的说明与可见水印；嵌入文档和OLE对象须另查内部属性。外部相对链接以文档所在位置为基准，另存后容易失效或指向错误路径，须按原稿核对指向并清理纯工作链接。
3. **运行只读来源检查脚本**：

```text
python -X utf8 <技能目录>/scripts/check_docx_metadata.py <交付文件或目录...>
```

若用户要求彻底删除特定固定字样，加传可重复参数 `--contains "需彻底删除的原文字样"`，排查正文（含删除修订和被删域指令）、批注、属性及图片；检查**对外净稿**时加传 `--clean-draft`，同步排查未接受的修订（`unfinished-revision`）、残留批注（`leftover-comment`）与黄色审阅高亮（`review-highlight`）；批量检查或接入脚本时可传多个文件/目录并加 `--json` 输出结构化结果。脚本以 `REVIEW <部件> [<位置>] (<类别>)` 格式输出精确位置（如 `[p#12]`、`[xml-comment#1]`、`[image-metadata]`）和风险类别（`local-path`、`tool-identity`、`contains#1`、`relative-external-target` 等），不会把敏感原文打印到终端。对确属文章主题、正常引文或有效链接的提示，核实后记录依据；清理并另存后须对同一交付文件复跑直至通过。

用于核对文字和渲染的临时副本放在工作目录；按要求分别提交带修订副本、对外净稿或修改说明，切勿把内部核对中间文件误当成最终稿交付。

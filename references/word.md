# Word 改稿

Word 文件同时作为内容来源和版式依据。有 DOCX 编辑技能时，用它处理文档结构和版式。按本技能判断表达和删改范围。

## 修改前

确认唯一输入和输出位置，保留原文件。读取正文、表格、标题、相关图表及批注，提取用户高亮标记并连同上下文判断；标记本身不是删除授权。

将改动记录为唯一定位、原文、新文或删除，并区分用户明确要求的删除与普通措辞调整。段落标识可用时优先使用，索引用于复核。标题、图表说明和表内文字属于授权范围时也可编辑，保留其编号及对应关系。

先查看已有修订、批注和标记。普通改稿保留既有修订和批注，除非用户要求处理它们。改动与既有修订相交时，先核对可见版本和原版本。无法安全写入时保留该处，说明位置和原因，继续改其余内容。

## 写回

优先使用既有精确修订工具。目标跨多个文字片段、包含域、书签、链接或既有修订时，按其结构选择现有的高级编辑流程；不要把整个段落清空后重新写入，也不要用纯文本重建全文。

插入和删除保留真实 Word 修订，沿用原字体和段落、表格样式。整段删除需同时标记段落结束符的删除，避免接受修订后残留空段。

审阅稿中的删除修订可被查阅或恢复。用户要求彻底清除的信息，以及工具身份、会话标识和工作路径，不能留在任何交付件的删除修订或批注里。对外净稿应先确定最终可见文本，再清除要移除的信息及残留。若同时交审阅稿，保留其他可审阅的改动，并说明哪些内容已彻底移除。

局部改稿工具的干净副本只处理本轮修改，可能仍含原有修订。发布净稿前，在副本里按已确定的最终文本处理旧修订。接受修订后仍可能有审阅高亮，逐处清理只用于审阅的标记，保留有内容作用的格式。

用户用于指出问题的黄色标记，相关位置处理完成后可清除；未能确定的位置保留标记并在正文外说明。清除问题标记不扩大为统一字体、颜色和版式。

修订署名使用用户给定的名称；未提供时采用中性的 Reviewer，并在交付说明中简要告知。不得使用生成工具或模型身份。

## 验证与交付

从同一改动记录核对最终可见文字，检查未授权范围、编号、表格及图表对应关系。核对技术法律含义、状态和单位；不能只比较数字串或段数。

验证文档包、修订和关系结构。对有修订的文档核对接受后的文字，并抽查拒绝时能否恢复相应原文。按改动影响渲染并检查页面，关注字体、表格、图表、跨页及空白段。

## 来源信息检查

对最终另存的每份交付件执行。局部写回可能复制原属性，转换或另存也可能重新写入属性。

1. 检查 `docProps/core.xml` 的作者、最后修改者和其他核心属性，`docProps/app.xml` 的应用程序、生成器和模板，`docProps/custom.xml` 及自定义数据中的工作标识。保留来自原稿或用户指定的真实署名及必要属性。清空工具写入的身份和来源值。修订及保留批注中的工具署名按前述署名规则处理。
2. 检查正文和页眉页脚、批注、删除修订、隐藏文字、对象说明、包内 XML 注释及外部关系中的工作路径、工具说明和会话标识。只清理应移除的信息。保留可读的引用、正常域及仍需保留的批注和修订关系。检查新增或可疑图片的属性和可见水印。嵌入文档和 OLE 对象须另查内部属性。
3. 对最终文件运行 [检查脚本](../scripts/check_docx_metadata.py)。脚本只读，输出部件和字段。若用户指定彻底删除的固定文字，加 `--contains "需删除的原文字样"` 检查是否仍在正文、删除修订、批注或属性中，可重复传入多个字样。对确属文章主题、引文或有效链接的提示，核对并记录依据。清理并另存后复查同一交付文件。未知工具名、嵌入对象和可见水印仍需按实际内容检查。

```text
python -X utf8 <技能目录>/scripts/check_docx_metadata.py <交付文件.docx>
```

脚本也会提示外部相对链接。这类链接以文档所在位置为基准，另存后可能指向别处或失效。按原稿核对指向，清理纯工作链接。另存后复查必要附件能否从交付位置打开，无法确认时列为待核。

单独清理属性时优先定点修改必要字段，避免把修订和批注作为匿名化内容一并删除。涉及包结构改动时复查关系和修订。

用于核对文字和渲染的临时副本放在工作目录。用户要求净稿或对照报告时提供相应版本，防止把为内部核对保留的文件当成最终稿。
